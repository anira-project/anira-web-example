Anira Web

Real-time neural audio processing in the browser

Demos

  • Simple Gain Stereo
    The minimal end-to-end Anira Web setup — a stereo gain model from the same JSON files a native host loads, on the module's built-in ONNX Runtime, and the foundation every other demo builds on.
  • Streaming Gain Stereo
    Delivers gain as a second Streamed tensor for sample-accurate updates, driven by a Web Audio LFO through a second audio node on the same handler.
  • JS Callback
    The simplest way to move inference out of WASM and into JavaScript — a passthrough JavaScript engine, defined in the worker module every inference Worker imports; the page starts and stops those Workers itself.
  • ONNX Runtime Web Backend
    Runs the same stereo gain model through the package's ONNX Runtime Web engine, swapping the built-in engine for onnxruntime-web in each inference Worker.
  • JS Copying
    A user-written custom inference engine — a class implementing anira's Engine interface in its own worker module, the template for wrapping any JS-side runtime.
  • PrePostProcessors
    A JavaScript stage in the audio worklet takes part in pre-processing, demonstrated by clamping the gain slider to [0, 1] on every block.
  • Steerable-NAFX (CNN)
    A CNN-based neural guitar amp whose model config declares each block's input as a sliding window with an overlap of 132 samples of past context for the convolutions to look back at.
  • GuitarLSTM (HybridNN)
    A hybrid LSTM/dense guitar amp whose JavaScript stage unfolds each block into a batched [2048, 1, 150] tensor of overlapping 150-sample context windows run in parallel.
  • RAVE: Magnetic Resonator Piano
    A streaming RAVE model whose convolution caches are one state tensor: the model config declares the pair, and anira carries the state from one 2048-sample inference to the next, each split across two threads by the ONNX Runtime Web engine. A mix slider sets the dry/wet balance with latency-aligned bypass.
